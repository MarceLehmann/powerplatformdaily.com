faq:
- question: Wann sollte ich Copilot Studio statt Agent Builder verwenden?
  answer: Copilot Studio eignet sich, wenn der Agent externe Systeme verbinden, Aktionen
    ausführen, Workflows starten oder APIs nutzen muss. Agent Builder ist für einfachere
    Projekte gedacht.
- question: Welche SharePoint-Inhalte können SharePoint agents als Wissen verwenden?
  answer: SharePoint agents können ausgewählte SharePoint-Websites, Bibliotheken,
    Ordner oder Dateien ohne Programmierung als Wissensbasis eines Agenten verwenden.
- question: Welche Entwicklungskontrolle bietet Microsoft Foundry für Agenten?
  answer: Microsoft Foundry unterstützt die Auswahl von Modellen, Frameworks, Laufzeitarchitektur
    und Integrationen sowie APIs, SDKs, CI/CD, Beobachtbarkeit und Bereitstellung.

## TL;DR

Microsoft beschreibt vier Einstiege für Agenten: SharePoint agents für vorhandene Inhalte, Agent Builder für deklarative No-Code-Agenten, Copilot Studio für Aktionen und Integrationen sowie Microsoft Foundry für tiefere Kontrolle über Modelle, Code und Architektur.

{% include curated-attribution.html %}

## Warum das wichtig ist

- Makers: Nutzt SharePoint agents oder Agent Builder für wissensbasierte Szenarien und wechselt zu Copilot Studio, sobald der Agent Aktionen ausführen muss.
- Admins/IT: Ordnet jede Option den benötigten Integrationen, Autonomie-, Governance- und Entwicklungsanforderungen zu, statt sie als austauschbar zu behandeln.
- Leadership/Business: Legt fest, wer den jeweiligen Agenten erstellen soll, und schafft den passenden Einstieg von No-Code bis zur professionellen Entwicklung.
